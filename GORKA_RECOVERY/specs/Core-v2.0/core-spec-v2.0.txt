GORKA — Core Technical Specification (FINAL — EXECUTION VERSION)
Version: 2.0 (Final)
Date: August 4, 2026
Purpose: Single source of truth for development

1. Core Principle
GORKA is a browser-based application deployed locally on client infrastructure. All business data stays on infrastructure the client controls. GORKA never stores customer data on its own infrastructure.
The only exception is the optional AI Copilot feature (see Section 3).

2. MVP Scope (6 Weeks)

Electron desktop app	Tauri (deferred)
Plain SQLite (no encryption)	SQLCipher (Phase 2)

CSV/Excel import + mapping	Multi-tenancy / RLS
Action Center (heuristics rules)	Local LLM
AI Copilot (simplified anonymization)	Full anonymization pipeline
Auto-backup (local folder)	Cloud backup (optional)
Health monitor (basic)	Advanced monitoring
Admin user management	Billing integration
License check (HTTP to GORKA)	Offline license files

3. The Honest AI Exception
Feature	Data Flow	Does it leave?
All core storage	Local SQLite	No
Local network sync	Within client office	No
Backup (optional)	To client's cloud account	No
AI Copilot	Anonymized context ? External AI Provider (client's key)	Yes — opt-in, disclosed
MVP Anonymization Rules:
    • Name ? "Debtor A", "Debtor B" (sequential per session)
    • Amount ? rounded to nearest 100
    • Everything else ? fully redacted ? "[REDACTED]"
    • No parsing of unstructured text
    • No classification
Positioning:
"Core data is fully local. AI Copilot is optional, transparent, and uses your own API key. No hidden transfers."

6. Critical Implementation Notes
Item	What You Must Actually Build
Electron + Node	Node is native in Electron. No sidecar, no IPC complexity.
SQLite Polling Queue	Single-threaded polling with lockedAt timeout (reset jobs stuck >5 min)
Optimistic Locking	Manual version field in Prisma — @updatedAt alone doesn't prevent overwrites
Polling Indexes	Must add @@index([assignedTo, status]) and @@index([dueDate]) to Action table BEFORE launch
AI Anonymization	Name?"Debtor A", Amount?rounded, rest?"[REDACTED]" — no parsing
License Check	Simple HTTP call to GORKA license server (e.g., /api/license/check). This carries NO debtor data — only license/account status.
Backup Recovery	Use PRAGMA integrity_check on backup file — simple and effective.

GORKA — Product Specification
Version: 2.0 (Complete)
Date: August 4, 2026

The Core Concept (One Product, Two Stages)
GORKA is a browser-based application deployed locally on client infrastructure. All business data stays on infrastructure the client controls. GORKA never stores customer data on its own infrastructure.
We build one product with a clear upgrade path:
    • Stage 1: Professional Edition — for small to medium agencies (self-serve, no IT needed)
    • Stage 2: Enterprise Edition — for banks and large institutions (IT-managed, scalable)
The architecture is designed so Stage 2 is an upgrade, not a rewrite.

STAGE 1: Professional Edition
What We're Building Now
Component	Technology	Why
Desktop App	Electron	Node.js native, ships fast
Frontend	React + TypeScript + Material UI	Robust ecosystem
Database	SQLite (plain, no encryption)	Embedded, zero-configuration
Data Access	Prisma ORM	Abstracts database — enables upgrade to PostgreSQL later
Backend	Node.js (native in Electron)	No sidecar, no IPC complexity
Multi-User Sync	Polling (10-second interval)	Simple, works for 5-10 concurrent writers
Authentication	JWT (local, admin-managed)	Session-only, no central server
AI	External AI Provider (OpenAI default) — client-managed key	Optional, transparent, opt-in
Job Queue	Custom SQLite polling loop	Simple, single-threaded, timeout recovery
Event Bus	Node.js EventEmitter	Simple, sufficient for single host
Backup	SQLite dump to local folder	Client-chosen location
Auto-Update	Electron autoUpdater	Essential for non-technical users
Licensing	HTTP check to GORKA license server	Minimal exception, no debtor data

What Stage 1 Does
Feature	Description
Multi-User	Admin, Supervisor, Collector roles. Up to 100 users total, ~5-10 concurrent writers.
Data Import	CSV/Excel upload with field mapping and automatic data cleaning.
Action Center	Smart daily task prioritization using research-backed heuristics (UK, Spain, Philippines, Indonesia rules).
AI Copilot	Generates message drafts using client's own API key. Simplified anonymization: Name ? "Debtor A", Amount ? rounded, rest ? "[REDACTED]".
Skip Tracing	Aggregates all contacts (phone, email, address) in one profile. Manual enrichment.
History & Audit	Full interaction log with immutable audit trail.
Compliance Dashboard	Data location report, audit log, key management report.
Backup & Restore	Auto-backup every 4 hours + on-demand. Simple restore flow.
Health Monitor	Database status, disk space, queue status, backup status, version, license.
Admin UI	User management, basic settings, billing placeholder.

Stage 1 Technical Limits
Limit	Details	Mitigation
Concurrent writers	~5-10 recommended	Queue writes, optimistic locking, retry on lock
Total users	100+ fine in practice	Reads are unlimited
Total records	100,000+ debtors	SQLite handles this easily
Database size	Up to 100GB	SQLite supports this
Sync	Polling (not real-time)	10-second interval is sufficient for small teams

Stage 1 Deployment
    1. Client downloads a single installer (Windows/Mac).
    2. One computer runs the app (the "host").
    3. Other employees connect via browser to http://gorka.local:3000 (or IP address).
    4. All data lives on the host machine.
    5. No IT setup required.

STAGE 2: Enterprise Edition
What We Add Later
Component	Upgrade	Why
Database	PostgreSQL (client's own server)	Removes SQLite write limits
Sync	WebSockets (real-time)	Better for larger teams
Multi-tenancy	PostgreSQL RLS	Data isolation between departments
AI	Local LLM (Ollama/Llama)	Fully local AI option
AI Anonymization	Full pipeline (parsing, classification)	More sophisticated data protection
Encryption	SQLCipher (proper key recovery)	Data at rest encryption
Backup	Cloud integration (S3, etc.)	More robust backup options
Job Queue	BullMQ with Redis	Scalable, reliable
Event Bus	Redis PubSub	Multi-server support
Infrastructure	Client-hosted server	IT-managed deployment
Mobile Access	Web-based (if server is accessible)	Remote work support
Advanced Compliance	More jurisdictions	International expansion
Billing	Full payment integration	For Enterprise pricing

What Stage 2 Adds
Feature	Description
PostgreSQL Database	Removes write contention. Supports 100+ concurrent writers.
Real-Time Sync	WebSockets. Changes appear instantly to all users.
Multi-Tenancy	One deployment can serve multiple departments with data isolation.
Local LLM	Fully local AI processing. No external calls. Optional, requires GPU hardware.
Full AI Anonymization	Parses unstructured text, identifies PII, classifies debt descriptions, maps responses back to real debtors.
Data at Rest Encryption	SQLCipher with proper key recovery (recovery keys, not hardware-bound).
Cloud Backup	Backup to client's own S3, Google Drive, or Dropbox.
Enterprise Job Queue	BullMQ with Redis. Reliable, retryable, priority queues.
Advanced Compliance	Support for more jurisdictions, automated rule updates.
Mobile Access	Collectors can work from anywhere (if server is accessible).
API Access	REST API for integration with client's existing systems.
White-Labeling	Custom branding for Enterprise clients.

Stage 2 Technical Limits
Limit	Details
Concurrent writers	100+ (no practical limit)
Total users	Unlimited
Total records	Unlimited (PostgreSQL scales)
Database size	Unlimited (PostgreSQL scales)
Sync	Real-time (WebSockets)
Deployment	Client's IT team (on-premise or private cloud)

Stage 2 Deployment
    1. Client's IT team deploys PostgreSQL on their own infrastructure.
    2. Client's IT team deploys the GORKA server (Node.js) on their own infrastructure.
    3. Employees connect via browser to the server (internal network or VPN).
    4. No data ever leaves client infrastructure (except optional AI, if enabled).
